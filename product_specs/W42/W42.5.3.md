## Objective

A visitor who has asked their device for reduced motion gets a calm site
everywhere, not just in the components that remembered to check. Every
focusable element shows the same clearly visible focus ring on both the sand
and navy surfaces. And the new pages from this week are covered by the
Lighthouse check.

## Background

The site animates with three different systems: **GSAP** (About pinning, the
hero, the board inertia, the menu), **Framer Motion** (events carousel, board
overlay), and **CSS** (`animate-tsa-float` and `animate-tsa-float-soft` in
`src/index.css`, used on the gallery background images). Reduced motion has been
handled spec by spec: W41.3.3 for the carousel, W38.3.3 for the board overlay,
W41.4.1 for the lightbox, W42.5.2 for the menu. `features_TODO.md` still lists
*"`prefers-reduced-motion` coverage across GSAP, Framer Motion, and the two CSS
float animations"* as open. W38.2.2 noticed back in W38 that the float
utilities might not respect it, and nobody checked.

The home → gallery **route transition** (`GalleryTransitionProvider`) is the
largest animation on the site: a crimson sweep across the whole screen. For
someone with a vestibular disorder, a full-screen sweep is exactly the kind of
motion the setting exists to stop.

Focus styling is in a similar state. Each component that remembered added its
own ring: gold on navy here, something else there, and the browser default
elsewhere. `features_TODO.md` lists *"Focus-visible styling on all interactive
elements."* A ring that's visible on sand can vanish on navy and the other way
round. One ring designed for both is simpler than a dozen local ones.

Finally, W41.5.3's Lighthouse check tests the home page and gallery. This week
adds `/events`, `/board` and `/join`, and nothing tests them.

## Specification

1. **Inventory every animation.** Search `src/` for GSAP calls, Framer Motion
   components and hooks, CSS `@keyframes`, `animate-*` utilities and
   `transition`. In the PR, make a table: where it is, what it does, whether it
   already respects reduced motion, and who owns the file this week.

2. **Fix the CSS floats.** Make `animate-tsa-float` and `animate-tsa-float-soft`
   do nothing under `prefers-reduced-motion: reduce`. Fix it where the utilities
   are defined, so every use is covered.

3. **Give the route transition a reduced-motion path.** Under reduced motion,
   home ↔ gallery is an instant swap or a short cross-fade: no sweep, no
   movement. The route still changes at the same point, and W42.5.1's focus
   move still happens after it. Don't change the full-motion version.

4. **Report the rest.** Anything in the inventory that doesn't respect reduced
   motion and lives in another track's file goes into `features_TODO.md` under
   "Accessibility audit," with the file, what moves, and the owning track. Post a
   summary in the group chat. Don't fix other tracks' files.

5. **One focus ring.** Add a focus-ring token in `src/index.css` and a base
   `:focus-visible` style that applies to every link, button, input, select,
   summary and element with a `tabindex`. Design it so it passes 3:1 against
   **both** the sand and navy surfaces, and against the crimson cards in the
   About section. A two-tone ring (an inner color plus an outer offset of
   another) is the usual way. Remove component-level rings in your own files
   that this replaces; leave other tracks' local rings, and list them in the PR.

6. **Never hide focus.** Search for `outline: none`, `outline-none` and
   `focus:outline-none` across `src/`. Each one either has a visible
   replacement nearby or is on an element that only ever receives programmatic
   focus (like `<main>` from W42.5.1). List any that don't in the PR and in
   `features_TODO.md`.

7. **Test the new routes in CI.** Add `/events`, `/board` and `/join` to the
   URLs in `lighthouserc.json` for any of those routes that have merged, in the
   same URL form the file already uses. Check that the next Lighthouse run on
   your PR reports them without 404s.

## Hints

- A `@media (prefers-reduced-motion: reduce)` block in `src/index.css` that
  targets the float utilities by name is the simplest fix. A global rule that
  kills every animation is tempting but also kills fades that help comprehension;
  be deliberate.
- Chrome devtools → Rendering → "Emulate CSS media feature
  prefers-reduced-motion" is the fastest way to test without changing your OS
  settings.
- `:focus-visible` shows the ring for keyboard focus and usually not for mouse
  clicks, which is what you want. `:focus` shows it for both.
- WCAG 2.2 "Focus Appearance" and "Non-text Contrast" (3:1) are the two
  criteria to read for the ring.
- `outline` follows `border-radius` in current browsers, so a rounded pill
  button gets a rounded ring.

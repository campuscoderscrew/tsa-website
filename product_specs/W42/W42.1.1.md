## Objective

The site gets an `/events` page that lists every upcoming TSA event, soonest
first, grouped by month. A visitor who finds one event in the carousel can see
everything the club has coming up, and an officer can link straight to the page
from Instagram.

## Background

TSA's intake form asked for **"a calendar"**. W41 built the foundation:
W41.3.2 created `src/data/events.ts` with ISO 8601 dates and upcoming/past
helpers, and shaped it so a Google Calendar feed could later produce the same
array. But the only place events appear is the home-page carousel, which shows
a handful of cards and nothing else. There is no page a visitor can bookmark or
an officer can share.

`features_TODO.md` sketches the calendar as "month grid or agenda list, past vs
upcoming, links to the Instagram post for each event." This feature builds all
three, one spec at a time:

- **W42.1.1 (this spec):** the route and an agenda list of upcoming events.
- **W42.1.2:** past events, grouped by school year (the "archive of previous
  events" TSA asked for).
- **W42.1.3:** a month grid view.

The Google Calendar question (`features_TODO.md`, open question 1) is still
open. This spec must not decide it. It reads events **only through the helpers**
from W41.3.2, so switching the data source later changes one file, not three
pages.

The site is a single-page app under `/tsa-website/`. `scripts/copy-404.mjs`
copies `index.html` to `404.html`, so a hard refresh on a deep link boots the
app and the router resolves it. That only works if the route is registered
correctly and every link to it respects the base path.

## Specification

1. **Register the route.** Add `/events` to the router in `App.tsx`. That's one
   line in Track E's file, so post in the group chat before you push.

2. **Follow the page conventions** in this week's README: one `<h1>`, a
   `<main id="main-content" tabIndex={-1}>`, and a document title of the form
   `Events · Thai Student Association at UMD`. W42.5.1's skip link and
   route-focus logic rely on that `id`.

3. **Use the brand, not a new look.** Eyebrow label, `LaiThaiDivider` and
   heading, the same pattern the home sections and the gallery use. Pick a
   surface (sand or navy) and say why in the PR. Colors come from tokens; a raw
   brand hex is a review blocker.

4. **Build `EventAgenda`.** It takes a list of events and renders them grouped
   by month ("November 2026"), soonest first. Each entry shows:
   - a date block (day and short month), formatted from the ISO string
   - title, venue and category
   - a link to the Instagram post if `instagramUrl` exists, with an accessible
     name that includes the event title, not just "Instagram"
   - a time, if the event has a date-time and not just a date

   Multi-day events (`end` set) show the range ("Nov 14–16"). Take the list as
   a prop instead of importing data inside the component: W42.1.2 will reuse it
   for past events.

5. **Read data only through the helpers.** The page imports the upcoming-events
   helper from `src/data/events.ts`. It does not import the raw array and filter
   it itself. If you need a helper that doesn't exist, add it to `events.ts`
   next to the others.

6. **Empty state.** Between semesters there may be no upcoming events. Show a
   friendly message that points to @umdtsa on Instagram, the same approach
   W41.3.2 took for the carousel. Never show an empty page with only a heading.

7. **Link to it from the site.**
   - Add an "Events" item to the slide-out menu (`menuItems` in `HomePage.tsx`,
     Track D's file — one line).
   - Add a "See all events" link under the home carousel in
     `UpcomingEvents.tsx`.

   Internal links must go through the router or the base path (see Hints). A
   plain `href="/events"` 404s on GitHub Pages.

8. **Prove the deep link works.** `npm run build && npm run preview`, open
   `/tsa-website/events` directly in a new tab, then hard-refresh it. Both must
   load the page, not a 404 and not the home page.

## Out of Scope

- Past events (W42.1.2)
- A month grid (W42.1.3)
- Fetching from Google Calendar
- An "Add to calendar" / `.ics` download (in `features_TODO.md`)
- Per-route Open Graph tags (crawlers don't run JavaScript, so a client-side SPA can't vary them; see `features_TODO.md`)

## Hints

- react-router's `<Link to="/events">` adds the `basename` for you. Look at how
  `StaggeredMenu` renders `menuItems` before you add one: if it renders a plain
  `<a href>`, you need `` `${import.meta.env.BASE_URL}events` `` there instead,
  and that causes a full page load. Work out which you have and say so in the PR.
- The time zone trap from W41.3.2 still applies. If its helpers already format
  dates safely, use them; don't write a second date formatter.
- `Intl.DateTimeFormat` can format the month heading too
  (`{ month: "long", year: "numeric" }`).
- Grouping by month is a `reduce` keyed on `YYYY-MM`. Sort the keys, don't trust
  insertion order.
- React 19 lets you render `<title>` inside a component and hoists it to
  `<head>`. Check the React version in `package.json`; if it's older, set
  `document.title` in an effect.

## Objective

A typo in a data file (a misspelled photo name, a duplicate id, a term written
`2025–26`) fails `npm run build` with a clear message, instead of shipping a
broken image to the live site. And next year's officers have a one-page guide
to adding their board without a developer.

## Background

W41.2.2 added `scripts/check-assets.mjs`, which fails the build when code
references a file that isn't in `public/`. It catches the pattern
`` `${import.meta.env.BASE_URL}logo.png` ``. It does **not** catch the data
files, and that's where most future content lives:

- `src/data/board.ts` stores photos as bare filenames (`"Alison.jpg"`) and
  the component adds `BASE_URL` (W38.3.1 step 4). The asset check can't see
  them.
- `src/data/gallery.ts` (W38.4.2) and `src/data/events.ts` (W41.3.2) do the
  same with images and videos.

These files are exactly what a club officer with no React experience will edit
next year, after the people who built the site have graduated. GitHub Pages is
case-sensitive, so `alison.jpg` works on their Mac and 404s in production. A
board archive (W42.2.1, W42.2.2) multiplies the number of entries and the number
of chances to get one wrong.

W38.3.1 asked for a comment explaining how to add a board member. A comment
inside a TypeScript file is the wrong place for someone who has never opened
one. They need a short guide, and a build that tells them exactly what they did
wrong.

## Specification

1. **Load the data, don't regex it.** The data files are TypeScript. Find a way
   for a Node script to import their exported arrays as real values. Options
   to look into: Node's built-in TypeScript type stripping (check which Node
   version CI uses in `deploy.yml` and whether a flag is needed), a small
   devDependency such as `tsx`, or Vite's own SSR loading. Pick one, say why in
   the PR, and make sure it runs in CI with `npm ci --ignore-scripts`.

2. **Check board data.** For every entry in `BOARD_MEMBERS`:
   - `id` is unique across all terms
   - `term` matches `YYYY-YYYY` and the second year is the first plus one
   - `photo`, when set, is a file in `public/` with **exactly** that case
   - required fields aren't empty strings
   - the current term (W42.2.1's rule) has at least one member

3. **Check the other data files that exist.** If `src/data/gallery.ts` and
   `src/data/events.ts` are on `main`, check that every referenced file exists
   with exact case, that ids are unique, and (for events) that `start` is a
   valid ISO date and `end`, if set, isn't before `start`. If a file doesn't
   exist yet, skip it with a one-line notice rather than failing.

4. **Fail loudly and helpfully.** Exit non-zero on any problem. Each message
   names the file, the entry's `id`, the field and what's wrong, and for a case
   mismatch, the filename that *does* exist ("`alison.jpg` not found; did you
   mean `Alison.jpg`?"). Report every problem in one run, not just the first.

5. **Wire it into `build`** next to `check-assets`, so the deploy workflow and
   the PR check (W41.2.3) both run it.

6. **Prove it.** On a scratch commit, break one thing per check (wrong case,
   duplicate id, `2025-26`, a date in the wrong format) and paste the build
   output in the PR. Then revert.

7. **Write `docs/HANDOFF.md`.** Audience: next year's TSA officer who has
   GitHub access and has never written code. Cover, step by step:
   - adding the new board (photo naming, where the file goes, the fields)
   - switching the site to the new board (W42.2.1's current-term rule)
   - adding an event and a gallery photo
   - what a red build means and how to read this script's message
   - who to ask

   Use GitHub's web editor in the instructions, not a terminal. Have someone
   who didn't write the script follow it once and note where they got stuck.

## Hints

- Node's `fs.readdirSync("public")` returns real filenames with their real
  case, even on macOS, whose filesystem is case-insensitive. Compare against
  that list; don't rely on `fs.existsSync`, which says yes to the wrong case on
  a Mac.
- Collect errors in an array and exit once at the end with
  `process.exitCode = 1`.
- If data files import from `@/…`, a plain Node import can't resolve the
  alias. Check before you pick a loading approach.
- `Date.parse` accepts strings that aren't ISO 8601. A regex for the shape plus
  a round-trip check is stricter.
- Writing for a non-developer: one action per step, the exact button names,
  and a screenshot where a button is hard to find.

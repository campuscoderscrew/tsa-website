## Objective

A keyboard user can jump past the navigation straight to the content on every
page. A screen-reader user can move between the page's regions, and hears that
the page changed when they follow a link to another route. This week adds three
new routes, so this has to be in place for all of them.

## Background

Earlier weeks fixed accessibility one component at a time: alt text (W38.3.2,
W38.4.2), the events carousel (W41.3.3), the board overlay (W38.3.3), the
gallery lightbox (W41.4.1). The site-wide items in `features_TODO.md` →
"Accessibility audit" are still open:

- **No skip-to-content link.** Keyboard users tab through the whole nav on
  every page before they reach anything.
- **Heading hierarchy.** Nobody has confirmed one `<h1>` per page and no
  skipped levels.
- **Landmarks.** Nobody has checked that each page has a `<main>` and that
  header, nav and footer are the right elements.

There's a single-page-app problem too. When react-router changes route, the
browser doesn't load a new page, so a screen reader announces **nothing** and
keyboard focus stays on the link that was clicked, which may no longer exist.
To a blind user, clicking "Events" appears to do nothing. With `/events`,
`/board` and `/join` arriving this week (W42.1.1, W42.2.1, W42.4.1), this goes
from one edge case (home ↔ gallery) to the main way people move around the site.

Home ↔ gallery is special: `GalleryTransitionProvider` runs an animated
transition before the route changes. Focus must move after the new page is
actually there, not during the animation.

This week's README defines a **page convention** every new page follows:
`<main id="main-content" tabIndex={-1}>`, exactly one `<h1>`, and a document
title. This spec is what makes that convention pay off.

## Specification

1. **Add a skip link.** `SkipLink` is the first focusable element on every page.
   It's hidden until focused, then appears in the top corner on a solid brand
   surface with AA contrast, and jumps to `#main-content`. Render it once in
   `App.tsx`, outside the routes. Pressing it must also move **focus**, not just
   scroll, so the next Tab continues from the content.

2. **Give the two existing pages a `<main>`.** Wrap the home page's content
   sections (not the menu, not the footer) and the gallery's content in
   `<main id="main-content" tabIndex={-1}>`. `HomePage.tsx` is Track D's file:
   change only the wrapper and the title, and post in the group chat first.
   Don't let `<main>` show a focus ring when it receives programmatic focus.

3. **Audit headings and landmarks** on home and gallery. In the PR, list every
   heading on each page with its level. Each page has exactly one `<h1>`, and
   levels don't skip (no `h2` → `h4`). Header, nav and footer are `<header>`,
   `<nav>` and `<footer>` (or carry the matching role). Fix what's in your files;
   for headings in other tracks' files, post the fix needed in the group chat and
   add it to `features_TODO.md` if it doesn't get done this week.

4. **Move focus on route change.** `useRouteFocus` runs in `App.tsx`. When the
   path changes (not on the first page load, and not for a hash change on the
   same page), it moves focus to `#main-content` and scrolls to the top.
   For the gallery transition, focus moves once the transition has finished.
   Read `GalleryTransitionProvider` and find the right moment; don't guess with a
   timeout.

5. **Set document titles.** Home and gallery each set a title following the
   README convention (`Gallery · Thai Student Association at UMD`; the home
   page can use the full name on its own). Screen readers announce the new title
   when focus moves, which is how the user hears "you're on a new page."

6. **Post the convention.** When this merges, post in the group chat that the
   skip link and route focus are live, and that every new page needs
   `id="main-content"` on its `<main>`. Check the routes that have merged by then
   and tell their owners if one is missing it.

## Hints

- The standard skip-link style keeps the link on screen but moved out of view
  until `:focus`. Look up why `display: none` and `visibility: hidden` don't
  work (a hidden link can't receive focus).
- `tabIndex={-1}` lets an element receive focus from script without becoming a
  Tab stop. Pair it with `outline: none` on that element only, never globally.
- react-router's `useLocation()` gives you the path. Store the previous path in
  a ref so the first render can be skipped.
- Gov.uk's and the WebAIM articles on skip links and "accessible client-side
  routing" are worth ten minutes each.
- Screen readers may not announce a title change by itself; moving focus to the
  `<main>` (or its `<h1>`) is what triggers the announcement. Test both and
  keep what works in both VoiceOver and NVDA if you can.

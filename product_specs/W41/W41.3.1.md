## Objective

Make the events carousel follow the Rules of Hooks, so it can't break
unpredictably and lint can pass. Clean up the W38 leftovers in the same file
while you're there. **The carousel should look and feel exactly the same
afterwards.**

## Background

`UpcomingEvents.tsx` renders five fanned cards with
`[-2, -1, 0, 1, 2].map((offset) => { ... })`. Inside that callback it calls
`useTransform` **seven times**. That's 7 of the 8 lint errors on `main`.

It works today only by luck. React tracks hooks by **call order**, and the
loop happens to always run five times in the same order. If anyone changes the
loop, it breaks. For example: rendering fewer cards when there are only two
events (which W41.3.2 may well do), or filtering past events out. Hooks would
then shift between cards, and you'd get either a crash ("Rendered fewer hooks
than expected") or cards animating with each other's values. This is the bug
W41.3.2 would walk straight into, which is why this spec comes first.

The same file also has W38 leftovers that belong to Track C:

## Specification

1. **Extract the per-card logic into its own component.** Everything inside
   the `.map()` callback that depends on `offset` (the seven `useTransform`s
   and the `motion.div`) moves into a component that receives what it needs
   as props. The `.map()` then just renders that component. Each card instance
   now owns its own hooks, so the number of cards can change safely.

   Work out what the new component needs: the shared `progress` motion value,
   `active`, the card's `offset`, `geom`, `dragControls`, and the item. Pass
   the `MotionValue` itself, not `progress.get()`. If you pass a snapshot, the
   card will stop animating during a drag. Take time to understand why.

2. **Keep `key` stable and meaningful.** The current key is
   `` `${item.id}-${offset}` ``. Think about what happens to React's
   reconciliation when you advance one card, and whether that key is what you
   want. Don't change the key's behavior in this spec unless you can explain
   the visual difference. Write down what you found in the PR either way.

3. **Behavior parity.** Record before and after on a desktop browser and a
   phone-width viewport: drag left, drag right, a short drag that snaps back,
   and video autoplay on the center card. Attach both recordings. They should
   be indistinguishable.

4. **Clean up the four leftovers** from the Background table:
   - Remove `font-epilogue` (the body font is inherited).
   - Turn the blob `fill` and the divider color into tokens. For the SVG, use
     `currentColor` plus a text class, the same way the ornament kit works.
   - Set the `h2` to one of the Fraunces weights Track B announced in W41.2.1.
     If that hasn't been posted yet, use `font-bold` (700 is loaded today).
     Retune `tracking-tighter` by eye. Uppercase serif usually wants *positive*
     tracking, not negative.

5. **Tell Track B when it merges.** W41.2.3 is blocked on you.

## Hints

- React docs, "Rules of Hooks", and the section on why hooks can't go in
  loops. Read it before you start; it's short.
- `useTransform` returns a `MotionValue`. Passing a `MotionValue` as a prop is
  normal in Framer Motion, and it does **not** re-render the child on every
  frame. That's the point of motion values.
- If cards "jump" after your refactor, compare what `active` is when the
  component first mounts against when the transform runs. Stale closures are
  the usual cause.

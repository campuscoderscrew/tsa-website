## Objective

Close out the W38 brand work. Headings should render in the display serif at
weights the browser actually has, with spacing that suits a serif. No brand
hex should be left in the files Track B owns.

## Background

W38.1.3 swapped the heading font to **Fraunces** and did the hard part. Four
things were left unfinished. A reviewer would catch each of them:

1. **Weights requested ≠ weights loaded.** `index.html` loads Fraunces at
   `400;700` only. The base layer sets headings to 400, which is fine. But some
   headings carry their own `font-semibold` (600) or `font-extrabold` (800).
   The browser can't render a weight it doesn't have, so it substitutes the
   nearest one. You get 700 where the code says 600, and 700 where it says 800.
   Either the code is lying or the `<link>` is incomplete.
2. **The fallback stack is wrong.** The `h1, h2, h3` rule in `src/index.css`
   reads `var(--font-display), ui-sans-serif, system-ui, sans-serif`. While
   Fraunces is loading (`display=swap`), headings flash in a sans. That's a
   bigger layout jump than a serif fallback would cause. W38.1.3's hints
   called this out.
3. **Sans-serif tracking on serif type.** The hero `h1` uses `tracking-tight`,
   and the About heading does too. Tight negative tracking is a geometric-sans
   habit. Fraunces has wide, high-contrast letterforms that collide when
   squeezed.
4. **Brand hex that W38.1.2 missed or that W38.2.2 re-introduced** in Track B's
   files:
   - `src/components/about/AboutUsScroll.tsx`: the `LaiThaiDivider` has
     `text-[#9B1B30]`.
   - `src/components/transitions/GalleryTransitionProvider.tsx`: the swipe
     graphic has `stroke="#9B1B30"`.
   - `src/components/staggered-menu/StaggeredMenu.tsx`: the `colors` fallback
     is `["#1e1e22", "#35353c"]`. Those are template greys that render only if
     the prop is dropped. W38.1.2 step 5 asked for brand-safe defaults.

The same kinds of leftovers in the **Board**, **Events** and **Gallery** files
are owned by those tracks and are listed in their own specs. Don't touch them.

## Specification

1. **Inventory heading weights.** Grep `src/` for every `h1`, `h2`, `h3` and
   every `font-display` usage. Note the weight each one asks for, whether
   that's set explicitly or inherited from the base layer. Put the list in your
   PR description.

2. **Pick the weight set, then make the code and the `<link>` agree.** Keep it
   to **two** weights. Choose them by looking at the real headings, not by
   picking numbers. Then change `index.html` to load exactly those two, and
   change any heading in *your* files that asks for a different weight.
   **Post the two weights in the group chat** so Tracks A, C and D use them for
   their headings this week.

   Fraunces is a variable font. Look up how Google Fonts requests a weight
   *range* versus individual weights, and whether that changes the download
   size. Then decide. Either answer is fine if your PR says why.

3. **Fix the fallback stack.** The heading rule and `--font-display` should
   both fall back to serif faces (`ui-serif, Georgia, serif`). Make sure
   there's one source of truth: the `h1, h2, h3` rule should use the token
   rather than repeat the stack.

4. **Retune tracking on the headings you own**: the hero `h1` and the About
   `h2`. Start from `tracking-normal` and adjust by eye at 375px and 1440px.
   Large serif display text sometimes wants a *little* negative tracking, but
   nowhere near `-0.06em`.

5. **Replace the three hex leftovers** listed in Background with tokens.
   - For the SVG stroke, look at how the ornament kit handles color
     (`currentColor`), and do the same thing instead of writing
     `stroke="var(...)"`.
   - For the `StaggeredMenu` fallback, use values from `TSA_COLORS`
     (`src/lib/brandColors.ts`). GSAP needs real color strings.

6. **Leave greys and whites alone.** `#fff`, `#111` and `#000` in
   `StaggeredMenu.css`, and `"#ffffff"` in `HomePage.tsx`, are neutral colors,
   not brand colors. This is the same rule as W38.1.2 step 7.

## Hints

- Fraunces has an optical-size axis (`opsz`). At very large sizes it switches
  to more delicate, higher-contrast shapes. If the hero looks too spindly or
  too heavy, that axis is why. You don't have to use it, but know it's there.
- `font-synthesis: none` in devtools is a quick way to see whether the browser
  is faking a weight. If the heading changes when you toggle it, the weight
  isn't loaded.
- In Tailwind v4, `--font-display` in `@theme inline` generates `font-display`.
  Changing the token's fallback list updates every heading that uses the
  utility.

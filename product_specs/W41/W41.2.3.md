## Objective

Get `npm run lint` to zero errors on `main`. Then add a GitHub Actions check
that runs lint and build on every pull request, so the "lint must pass" rule
is enforced by a machine instead of a checkbox.

## Background

Every W38 spec's Definition of Done said `npm run lint` must pass. It has never
passed on `main`. There are 8 errors:

- **7 × `react-hooks/rules-of-hooks`** in `UpcomingEvents.tsx`. This is a real
  bug: `useTransform` is called inside `.map()`. **Track C fixes it in
  W41.3.1.** That's why this spec waits for it.
- **1 × `react-refresh/only-export-components`** in
  `src/components/transitions/GalleryTransitionProvider.tsx`. That file exports
  a component (`GalleryTransitionProvider`) and a hook
  (`useGalleryTransition`). Vite's Fast Refresh can only hot-swap a module that
  exports nothing but components. With the hook in there, editing the provider
  forces a full page reload in dev and drops your state. **This one is yours.**

Deploys already run on GitHub Actions: `.github/workflows/deploy.yml` builds
and publishes on every push to `main`. Nothing runs on pull requests, so a PR
that breaks the build is discovered only *after* it merges, when the deploy
fails and the live site stops updating.

## Specification

1. **Fix the Fast Refresh error.** Move whatever isn't a component (the hook,
   and probably the React context it reads) into its own module. Update the
   three files that import `useGalleryTransition`. Behavior must not change:
   test home → gallery → home and the board "View gallery" button.

2. **Confirm lint is clean.** With W41.3.1 merged, `npm run lint` on `main`
   should report **0 problems**. If it doesn't, find out what's left and who
   owns the file before you fix anything.

3. **Add a PR check workflow** (`ci.yml`):
   - triggers on `pull_request` targeting `main`
   - installs exactly the way `deploy.yml` does (`npm ci --ignore-scripts`,
     Node 22, npm cache). Read the comment in `deploy.yml` for why
     `--ignore-scripts` is there.
   - runs `npm run lint`, then `npm run build`
   - read-only permissions (`contents: read`). A PR check should never be able
     to write to the repo or publish Pages.
   - `concurrency` keyed on the PR, so a new push cancels the stale run

4. **Decide whether `deploy.yml` should lint too.** Arguments go both ways:
   it's a second safety net, but it also means a lint rule change can block an
   urgent content fix. Pick one and write a sentence in the PR.

5. **Make the check required.** Find where branch protection (or a ruleset) is
   configured for `main` and what it takes to make `ci` a required check. You
   probably don't have admin rights. Write the exact click path in the PR so
   Brennen can flip it.

6. **Update the repo README.** One short paragraph under Deployment: PRs run
   lint and build, and a red check means don't merge.

## Acceptance Criteria

- [ ] `npm run lint` on your branch reports 0 problems
- [ ] `GalleryTransitionProvider.tsx` exports only components; editing it in `npm run dev` hot-swaps without a full page reload
- [ ] Home → gallery → home transition and the board's gallery button still work

- [ ] Click path for making the check required is in the PR

## Out of Scope

- Fixing the `rules-of-hooks` errors (W41.3.1)
- Adding Prettier, tests, or Lighthouse CI. Good ideas; add them to `features_TODO.md`.
- Changing ESLint rules to make errors go away. Turning a rule off is not fixing it.

## Hints

- The `react-refresh` rule only cares about what the file **exports**. A
  context object created with `createContext` is not a component either.
- The GitHub docs page "Using concurrency" shows the
  `${{ github.workflow }}-${{ github.ref }}` pattern for this.
- A PR from a fork gets a read-only token whatever you set. PRs in this repo
  come from branches in the same repo, but it's worth knowing why
  `pull_request` (not `pull_request_target`) is the safe trigger.

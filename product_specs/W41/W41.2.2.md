## Objective

Make the browser tab, the iOS home-screen icon and link previews work on the
live site. Stop shipping about 1.4 MB of images that are unused or far larger
than they need to be.

## Background

W38.5 created the right files but didn't wire them all up. On `main` today:

| Problem | Evidence |
| --- | --- |
| **The favicon link is broken.** | `index.html` has `<link rel="icon" type="image/jpeg" href="/favicon.png">`. There is no `public/favicon.png`; the real files are `favicon.svg` and `favicon-32.png`. The `type` is also wrong. The tab shows the browser's default icon. |
| `apple-touch-icon.png` is never referenced | The file exists (180×180, correct), but no `<link rel="apple-touch-icon">` points at it |
| `favicon.svg` is **340 KB** | It's an auto-traced bitmap with thousands of path points. A favicon SVG should be a few KB. Browsers download it on every first visit. |
| `logo.png` is **428 KB at 1000×1000** | The largest it's ever shown is about 72px tall (footer) and 64px (menu). That's 14× more pixels than a 2× retina display needs. |
| Twitter/X card is incomplete | `twitter:card` is set, but there's no `twitter:title`, `twitter:description` or `twitter:image`. X *usually* falls back to the OG tags. Discord and iMessage are less forgiving about some combinations. Verify; don't assume. |
| No canonical URL or `theme-color` | `theme-color` tints the mobile browser's address bar. Navy would make the site feel like its own app on a phone. |
| Dead files in the repo | Root `thai.jpg` (398 KB; W38.5 was supposed to delete it), `public/lotus_flower.png` (188 KB, imported nowhere), `public/vite.svg`, `src/assets/react.svg`, all Vite template leftovers |

Remember the base-path rule from the repo README: **Vite rewrites
root-relative paths in `index.html` at build time**, so `/favicon.svg` in
`index.html` becomes `/tsa-website/favicon.svg` in `dist/`. That rewrite does
**not** apply to absolute URLs (`https://…`), which OG tags need anyway.

## Specification

1. **Wire up the icon set.** Use an SVG favicon with a 32px PNG fallback and
   the Apple touch icon. Use correct `type`s, and use `sizes` where it means
   something.

2. **Shrink `favicon.svg`.** Pick one approach and say which in the PR:
   - Simplify the traced paths. SVGO, plus a tracing tool with a lower detail
     setting, can do it. The logo has fine detail that won't survive at 16px
     anyway, so a simpler mark is *better* here, not worse.
   - Or drop the SVG icon and rely on PNGs (`favicon-32.png`, plus a 16px if
     you think it's needed).

   Target: **under 10 KB**, and recognizably TSA's logo at 16px in a real
   browser tab.

3. **Resize `logo.png`.** Work out the largest size it is ever displayed at
   (check the hero, the menu, and the footer at 1440px). Export at 2× that
   size, keep the alpha channel, and compress. Target: **under 60 KB**. Check
   the edges on the navy footer for halos. W38.5 worked to get those clean, so
   don't undo it.

4. **Complete the social tags.** Add `twitter:title`, `twitter:description`
   and `twitter:image`, plus `og:image:width`, `og:image:height` and
   `og:image:alt`. Add `<link rel="canonical">` with the absolute live URL.
   Add `theme-color` set to the navy. Look up whether it can differ in light
   and dark mode, and decide whether that matters here.

5. **Delete the four dead files.** Before deleting each one, `git grep` its
   filename across the repo (`src/`, `index.html`, `scripts/`, `README.md`).
   If anything references it, don't delete it; say so in the PR.

6. **Verify against the build, not the dev server.** Run `npm run build`,
   then open `dist/index.html` and check that every icon `href` starts with
   `/tsa-website/`. Then `npm run preview` and load the page with the network
   tab open: no 404s.

7. **After merge, verify the live site.** Paste the live URL into Discord (or
   use opengraph.xyz) and screenshot the preview into the PR thread.

## Hints

- `sips` (macOS), `magick` (ImageMagick), Squoosh (squoosh.app, in the
  browser) and `pngquant` all resize and compress PNGs. Squoosh is the easiest
  if you've never done this before.
- Browsers cache favicons aggressively. If you're looking at a stale icon, open
  the page in a private window before deciding your change didn't work.
- `type="image/svg+xml"` is the MIME type for SVG favicons.

## Objective

When someone searches for the UMD Thai Student Association, the site should be
something Google *can* show. Every route returns HTTP 200 with the right
canonical URL. Google is told which pages exist. The home page describes the
club in a form search engines can read.

## Background

The site went live for the first time in W41.0. Nobody has checked what a
crawler sees, and there are two problems you won't spot in a browser.

**1. Every route except home returns a 404 status.** GitHub Pages has no
server-side routing. The build copies `index.html` to `404.html`
(`scripts/copy-404.mjs`), so a direct load of `/tsa-website/gallery` serves
`404.html`. React Router then renders the gallery, and to a person it looks
fine. But the HTTP status is **404**, and search engines generally don't index
404 pages. Check it yourself:

```bash
curl -sI https://campuscoderscrew.github.io/tsa-website/          | head -1
curl -sI https://campuscoderscrew.github.io/tsa-website/gallery   | head -1
```

The fix is cheap. GitHub Pages serves `dist/gallery/index.html` for
`/tsa-website/gallery/` **with a 200**. A small post-build script can copy
`index.html` into a folder for each route. It isn't real prerendering, since
the HTML is still the empty SPA shell, but it gets the status right.

**There's a trap in that fix.** W41.2.2 adds
`<link rel="canonical" href="https://…/tsa-website/">`. If you copy
`index.html` unchanged, `/gallery/` will tell Google *"my canonical is the home
page."* Google then treats the gallery as a duplicate of home and drops it.
Each copy needs its own `canonical` and `og:url`.

**2. `robots.txt` probably can't work here.** `features_TODO.md` lists
"robots.txt, sitemap.xml". Look up *where* crawlers request `robots.txt`
(RFC 9309, or Google's robots.txt docs). This is a **project** site under
`/tsa-website/`, not the root of `campuscoderscrew.github.io`. Work out what
that means for a `public/robots.txt` before you write one. The sitemap still
helps, but it has to reach Google some other way.

**3. Structured data.** A JSON-LD `Organization` block on the home page tells
search engines the club's name, logo, parent university and social profiles.
It doesn't produce a fancy search result by itself. It's what feeds a
knowledge panel, and it ties the Instagram account to the site. Event markup
is a bigger and better win, but it needs W41.3.2's data and is left for a
later spec.

## Specification

1. **Confirm the problem.** Run the two `curl` commands above against the live
   site and paste the output into the PR. List every route in the router
   (look where `createBrowserRouter` / `<Routes>` is defined) and curl each one.

2. **Write `scripts/route-pages.mjs`**, in the same style as `copy-404.mjs`.
   It runs after `vite build` and:
   - holds **one list of routes**, with a comment pointing at the router file
     it has to stay in sync with
   - for each route except `/`, writes `dist/<route>/index.html`, a copy of
     `dist/index.html` with the `canonical` href and the `og:url` content
     rewritten to that route's absolute URL
   - writes `dist/sitemap.xml` from the same list, with absolute URLs
   - **exits non-zero** if `dist/index.html` has no canonical tag to rewrite.
     That way, if someone removes it later, the script fails loudly instead of
     quietly writing copies that all point at home.

   Add it to `build` after the 404 copy.

3. **Pick the trailing-slash form and use it everywhere.** GitHub Pages
   serves a folder's `index.html` at `/gallery/` and redirects `/gallery` to
   it. Decide which form is canonical (hint: the one that returns 200 without a
   redirect). Use it in the canonicals, the sitemap and the `og:url`s. Check
   that React Router still renders the right page at `/tsa-website/gallery/`.

4. **Decide about `robots.txt`.** Write two or three sentences in the PR:
   where crawlers look for it, whether a file in `public/` would ever be read,
   and so what you did. If it would never be read, **don't add it**. W41.2.2
   just spent time deleting files that do nothing. Update the
   `features_TODO.md` item to match.

5. **Add the JSON-LD** to `index.html`, in a
   `<script type="application/ld+json">` block:
   - `@type`: `Organization`
   - `name`: the club's official name. Check how UMD's student org directory
     (TerpLink) lists it, not what we've been calling it.
   - `url`: the absolute live URL
   - `logo`: the absolute URL of `logo.png`
   - `parentOrganization`: the University of Maryland, as a
     `CollegeOrUniversity` with its own `name` and `url`
   - `sameAs`: the real social profile URLs from W38.6's footer. If W38.6
     hasn't merged, use only the ones you can confirm (the Instagram is
     @umdtsa). Add a `TODO` comment in the PR, not in the JSON (JSON has no
     comments).

   Validate it with both Google's **Rich Results Test** and the
   **Schema Markup Validator** (validator.schema.org). Screenshot both. Rich
   Results will probably say "no rich results detected". That's expected for
   `Organization`. What matters is **no errors** in either tool.

6. **Prepare Search Console** (the sitemap's only route to Google, if
   step 4 went the way it probably will). You can't do this part alone. A
   property needs an owner, and that should be Brennen, not a student's
   personal account. In the PR, write:
   - which property type to add, and why a *Domain* property isn't possible
     on `github.io`
   - which verification method to use. Prefer one that **doesn't** touch
     `index.html` again, such as the HTML-file method (the file goes in
     `public/`).
   - the click path to submit `sitemap.xml` once it's verified

   If Brennen does it during the sprint, add the verification file in a
   follow-up commit and screenshot the sitemap's "Success" status.

7. **Verify against the live site after merge.** Re-run the curls from step 1
   (every route should be `200`), load `/tsa-website/sitemap.xml`, and run
   Google's Rich Results Test on the **live** URL, not pasted code.

## Hints

- Rewrite the tags with a string replace or a regex anchored on
  `rel="canonical"`. You don't need an HTML parser for two tags you control.
  Make the script fail if the replace didn't match anything.
- The sitemap protocol (sitemaps.org) is small: `urlset`, `url`, `loc`. Google
  ignores `priority` and `changefreq`, and only uses `lastmod` if it's
  accurate. Leave all three out rather than make them up.
- `curl -sI` follows nothing by default, so a `301` on `/gallery` (no slash)
  is expected and tells you the redirect is there.
- `import.meta.env.BASE_URL` isn't available in a Node build script. Hardcode
  the live origin and base path once, at the top of the script, next to a
  comment pointing at `vite.config.ts`.

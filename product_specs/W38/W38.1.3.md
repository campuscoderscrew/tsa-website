## Objective

Give the site a display typeface with some character, so headings stop reading
like a generic SaaS landing page and start matching the elegant, festive
lettering TSA actually uses on their own material.

## Background

The site loads **Manrope** and **Epilogue** — two competent, extremely neutral
geometric sans faces. They are the default choice of roughly every startup
template on the internet. Nothing is wrong with them, and that is precisely the
problem: they are why the site "looks kind of basic."

Look at what TSA actually publishes. Across their Instagram, their recurring
headline treatment is a **high-contrast serif** — the Songkran, Spring Picnic,
Board Applications and Valentine's GBM posts all use an elegant serif display
with generous letter spacing, sitting on a soft background. Their other register
is playful cut-out collage lettering for board introductions. Neither of those is
a geometric sans.

The brief asks for "a fun but professional and clean look." A serif display over
a clean sans body is exactly that pairing, and it's a two-font system rather
than a three-font one, which keeps the page fast.

There's a second, quieter problem: **Epilogue is loaded on every page load and
used in exactly one place** — the event subtitle line in `UpcomingEvents.tsx`.
That's a whole webfont family downloaded for one line of text.

## Files You'll Touch

```
index.html        modify  (font <link> tags)
src/index.css     modify  (font tokens, @theme, base heading styles)
```

If removing Epilogue means touching `UpcomingEvents.tsx`, that's one class name
and it's fine — mention it in the PR.

## Specification

1. **Pick a display serif.** It must be on Google Fonts (the project loads fonts
   from there already), and it must have a genuinely high stroke contrast — the
   elegance comes from thick-thin variation, and a low-contrast serif will just
   look like a different sans.

   Reasonable candidates: **Cormorant Garamond**, **Playfair Display**,
   **Libre Baskerville**, **DM Serif Display**. Evaluate at least two before
   choosing. Judge them by typing the actual strings the site uses — "Thai
   Student Association", "our board members", "Upcoming Events" — not by the
   specimen paragraph.

   Write one short paragraph in the PR on why you picked what you picked.

2. **Load exactly the weights you need.** Most likely two (a regular and a
   semibold or bold). Every extra weight is another file over the wire. Keep
   `&display=swap` — it's already there and it's correct.

3. **Drop Epilogue** unless you can point at a real reason to keep it. One
   subtitle line does not justify a font family. Replace that usage with the
   body font.

4. **Register font tokens** in `src/index.css`, following the existing pattern
   (`--font-manrope` is already there in `@theme inline`):

   ```
   --font-display   the new serif — headings only
   --font-body      Manrope — everything else
   ```

   Name them by *role*, not by typeface name. `--font-display` survives a font
   change; `--font-cormorant` does not.

5. **Apply to headings in the base layer.** `src/index.css` already has an
   `@layer base` block styling `h1, h2, h3` with Manrope at weight 600. Point
   that at `--font-display` instead. Setting it once in the base layer means
   every heading in the codebase picks it up without touching a component.

   Watch out: some headings set their own font class. Grep for `font-manrope` in
   `src/` — the hero `h1` and both `UpcomingEvents` headings do. Those explicit
   classes will override your base rule. Decide per heading whether it should
   become display type or stay sans, and be deliberate about it.

6. **Retune the heading sizes and spacing.** A serif at a size tuned for a
   geometric sans will look wrong — usually too small and too tightly tracked.
   Expect to loosen `letter-spacing` on large display text (several headings
   currently use aggressive negative tracking like `tracking-[-0.06em]`, which is
   a sans-serif idiom and will damage a serif).

7. **Add a `line-height` that suits display type.** Headings currently rely on
   Tailwind defaults or one-off `leading-[0.92]` values. Serif display type at
   large sizes usually wants tighter leading than body text but looser than
   `0.92`. Check the multi-line headings — "our board members" wraps on mobile.

8. **Thai script support — read this even though it isn't work this week.** If
   the site ever renders Thai text (event names in Thai, a bilingual tagline),
   Latin fonts have no Thai glyphs and the browser will fall back to something
   ugly and unstyled. **Noto Sans Thai** and **Noto Serif Thai** are the standard
   answer. Do not load them now — nothing on the site uses Thai script yet, and
   loading an unused font family is the mistake you just fixed with Epilogue.
   Instead, note it in `features_TODO.md` so it isn't rediscovered later.

- Loading Thai fonts
- Restyling body text

## Hints

- Test on the real strings at the real sizes. A font that looks great at 14px in
  a specimen can fall apart at `text-7xl`.
- Font loading causes layout shift. `display=swap` shows fallback text first and
  swaps — you can reduce the jolt by choosing a fallback stack whose metrics are
  close to the webfont. The tokens already have `ui-sans-serif, system-ui` as
  fallbacks; a serif needs a serif fallback (`ui-serif, Georgia, serif`).
- Cormorant Garamond in particular renders optically small — you will probably
  need to size it up relative to the sans it replaces.
- `@layer base` styles are lower-specificity than utility classes on purpose,
  which is why `font-manrope` in a component wins. That's the cascade working
  correctly, not a bug.
- The hero `h1` has no explicit weight and inherits 600 from the base layer.
  Many display serifs look better at 400–500 at large sizes.

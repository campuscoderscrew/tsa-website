## Objective

Build a small set of reusable SVG ornament components drawn from Thai visual
tradition, so the site has a decorative vocabulary of its own instead of the
generic blurred blobs and abstract scribbles it uses now.

This spec builds the kit. W38.2.2 puts it on the page.

## Background

TSA's brief is explicit:

> feature elements of **iconic Thai symbols** within the website

The site currently contains zero Thai visual references. What it does have:

- two blurred colored blobs in `BoardMembersSection.tsx` — generic 2020s
  landing-page decoration
- an abstract squiggle and an organic blob shape in `UpcomingEvents.tsx`
- `public/lotus_flower.png`, which is **committed but never imported anywhere**

That last one is telling. Someone already knew the site needed Thai motifs.

Meanwhile TSA's own Instagram is full of usable references: ornate **lai thai**
border patterns framing their board application posts, temple and prang
silhouettes in their highlight covers, lotus and krathong imagery from Loy
Krathong, and the tricolor flag bar as a recurring device.

The trap to avoid: throwing a large temple photo behind a section and calling it
done. The brief says "colorful but not overwhelming" and "clean." Ornament should
be structural and restrained — borders, dividers, corner marks, small repeating
units — not wallpaper.

## Specification

1. **Create `src/components/ui/thai-ornament.tsx`** exporting at least these
   three components. Keep them in one file — they're small and they share a
   visual language.

   **`<LaiThaiDivider />`** — a horizontal ornamental rule for separating
   sections. Based on the repeating *kranok* (flame/tendril) motif that runs
   along Thai temple borders. Should read as a delicate line of ornament, not a
   heavy band. Must tile or stretch cleanly to any width.

   **`<ThaiCorner />`** — a corner flourish for framing cards and headers. One
   drawing, rotatable to all four corners via a prop.

   **`<PrangSilhouette />`** — the stepped tower silhouette of a Thai prang or
   chedi. This is the single most recognizable Thai architectural shape and it's
   already in TSA's own highlight covers. Useful as a watermark or a section
   backdrop at low opacity.

2. **Draw them as inline SVG.** Not images, not icon-font, not `<img>` tags.
   Inline SVG can inherit color from CSS, which is the entire point — the same
   ornament has to work in gold on navy and in navy on sand.

3. **Use `currentColor` for every stroke and fill.** Then a consumer writes
   `<LaiThaiDivider className="text-tsa-gold-500" />` and it just works. Do not
   hardcode colors inside the components. If a component genuinely needs two
   colors, take the second as a prop with a sensible default.

4. **Every component takes `className`** and spreads it onto the root `<svg>`,
   so consumers control size, color, opacity and positioning with utilities. Follow
   how the existing decorative SVGs in `UpcomingEvents.tsx` are written — they
   already do the `className` + `viewBox` + `aria-hidden` pattern correctly.

5. **Mark them decorative.** Every ornament gets `aria-hidden="true"` and
   `focusable="false"`. These carry no information; a screen reader announcing
   "image" fourteen times is a real harm. There is no exception to this in this
   spec — if an ornament ever needs to convey meaning, it needs a `<title>` and a
   conversation first.

6. **Keep the path data small.** These are decorations that may appear a dozen
   times on one page. Target under ~2KB of path data each. If you're tracing from
   a reference and end up with a 40KB path, simplify it — the detail will be
   invisible at the sizes these render at anyway.

7. **Type the props properly.** Extend `React.SVGProps<SVGSVGElement>` so
   consumers get `className`, `style`, `aria-*` and the rest for free rather
   than you declaring them one at a time.

8. **Build a temporary preview.** Render all three at several sizes and colors
   somewhere you can look at them — a scratch route, or temporarily at the bottom
   of `HomePage.tsx`. **Remove it before you open the PR** and screenshot it for
   the PR description instead.

9. **Sourcing — read this carefully.** If you adapt path data from anywhere
   online, it must be public domain or a license that permits commercial-ish use
   with attribution, and you must record the source and license in a comment at
   the top of the file. Traditional Thai motifs are centuries old and the *motif*
   is not owned by anyone — but a specific modern SVG rendering of one is owned
   by whoever drew it. Those are different things. When in doubt, draw it
   yourself from a photograph; these shapes are simpler than they look.

## Hints

- Search terms for reference imagery: *lai thai*, *kranok*, *lai kanok*,
  *Thai temple border pattern*, *chedi silhouette*, *prang*.
- For a tiling divider, draw **one** repeat unit in a narrow `viewBox` and
  repeat it — either with `<pattern>` + `<rect>`, or by mapping the unit N times.
  Think about which handles arbitrary widths better before you commit to one.
- `preserveAspectRatio` is what stops a stretched divider from looking smeared.
  Worth understanding before you fight it.
- Draw at a round `viewBox` size (`0 0 100 100`) and let consumers scale with CSS.
- `vector-effect="non-scaling-stroke"` keeps stroke weight constant as an SVG
  scales — useful for the divider, possibly wrong for the corner. Try both.
- Simplify aggressively. At 24px tall nobody can see the difference between 200
  path nodes and 40.
